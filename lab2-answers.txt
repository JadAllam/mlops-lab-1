Q1 - Look at pyproject.toml and uv.lock. What changed?

pyproject.toml got mlflow, scikit-learn, torch and torchvision as dependencies,
plus the pytorch cpu index for torch and torchvision.
uv.lock went from 2 packages to 105, all locked with exact versions and hashes.


Q2 - What is --backend-store-uri used for? What is --default-artifact-root used for?
     What is the difference between the metadata and the artifacts?

--backend-store-uri        where the metadata goes (mlflow.db)
--default-artifact-root    where the artifacts go (./mlruns)

Metadata is experiments, runs, params and metrics.
Artifacts are files, like the saved model.


Q3 - Why shouldn't mlflow.db and mlruns/ be tracked by git, and why not by dvc either?

git: they are run outputs, not code, and they get big (45MB model per run).
dvc: dvc is for versioning data, mlflow already stores and versions the runs.


Q4 - What happens the first time you call set_experiment with a name that doesn't exist yet?

mlflow creates it. food11 shows up in the UI next to Default.


Q5 - What is the difference between log_param and log_metric? Why does log_metric
     take a step argument and log_param doesn't?

log_param is a fixed value for the run, like lr. log_metric is a value that changes
during training, like the loss.
A metric is logged every epoch so step says which epoch it's from. A param is
logged once so it doesn't need one.
